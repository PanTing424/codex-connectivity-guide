# Codex 电脑与安卓连接排查指南

Windows 使用 ProxyBridge 配置 Codex 进程代理，以及安卓 v2rayNG 的 DNS 故障排查。

本项目记录实际排查过程。已验证电脑进程代理生效、电脑可以生成配对二维码、手机普通聊天恢复；手机远程配对最终是否成功仍需单独验证。

- [Word 版教程](docs/Codex远程连接代理配置教程.docx)

- [ProxyBridge 配置文件](configs/Codex-v2rayN.pbprofile)

配置文件仅适用于本机 SOCKS5 `127.0.0.1:10808` 且未开启代理认证的情况。导入前请核实自己的端口。

## 两端分别解决什么问题

| 位置 | 现象 | 本案例采用的方法 |
| --- | --- | --- |
| Windows 电脑 | 系统代理已开启，部分 Codex 外部连接仍走直连 | ProxyBridge 按进程转发 `ChatGPT.exe` 和 `codex.exe` 的 TCP 连接 |
| 安卓手机 | 扫码停在正在配对，普通聊天也发不出，出现域名解析错误 | 在启用本地 DNS 的基础上，将远程 DNS 改为 `https://1.1.1.1/dns-query` |

两种方法解决的是不同层面的问题，并非所有连接故障的通用修复。节点和订阅无需因本案例的 DNS 修改而更换。

## 使用 ProxyBridge 配置 Codex 进程代理

Windows 与 v2rayN 逐步操作教程

GitHub 在线教程与下载：[https://github.com/PanTing424/codex-connectivity-guide](https://github.com/PanTing424/codex-connectivity-guide)

适用场景：Codex 可以聊天，但在桌面端点击允许远程控制时提示“无法启用远程控制，请重试”；开启 TUN 后反而无法联网。

本教程通过 ProxyBridge，把 Codex 指定进程的 TCP 连接转交给已在运行的 v2rayN 本地 SOCKS5 代理。ProxyBridge 本身不提供代理节点，不能替代 v2rayN。

### 先明确适用范围

这是一种针对代理覆盖问题的排查和配置方法，并非所有远程控制故障的通用修复。账号权限、工作区限制、设备验证、客户端版本和服务异常，也可能导致相同提示。

本次案例已验证：ChatGPT.exe 与 codex.exe 的新连接从 Direct 变成经 SOCKS5 代理。本教程整理时，手机配对和远程控制最终成功与否仍待验证。

### 操作前准备

1. 一台 Windows 电脑，已安装并登录 Codex 桌面应用；手机已安装官方 ChatGPT 应用。

2. v2rayN 已运行，当前节点可用；先确认电脑上的 Codex 和网页都能正常使用。

3. 如果 TUN 曾导致断网，保持 TUN 关闭，保留原先可用的系统代理设置。

4. 安装 ProxyBridge 时需要 Windows 管理员授权。只使用官方发布包。

### 你将完成的操作

确认本地端口 → 安装 ProxyBridge → 添加 SOCKS5 代理 → 添加 Codex 规则 → 查看代理日志 → 重新启用远程控制并扫码配对。

## 第一步 确认 v2rayN 的代理端口

本案例使用 127.0.0.1:10808。127.0.0.1 表示当前电脑，10808 是本地代理监听端口。其他人的端口可能不同，不能直接照抄。

### 在 v2rayN 中查找实际端口

1. 打开 v2rayN，确认已选择可用节点，程序正常运行。

2. 查看主窗口底部的本地 SOCKS 或混合端口信息；若未显示，进入设置中的参数设置，查找本地监听端口或 SOCKS 端口。不同版本位置可能不同。

3. 记下支持 SOCKS5 的实际端口。如果你只找到 HTTP 端口，稍后应选择 HTTP 类型，不能把协议与端口混用。

4. 保持 v2rayN 开启。配置 ProxyBridge 时不需要开启 TUN。

| 设置项 | 本案例填写值 | 如何判断 |
| --- | --- | --- |
| 代理协议 | SOCKS5 | 本地端口必须支持 SOCKS5 |
| 代理主机 | 127.0.0.1 | ProxyBridge 与 v2rayN 在同一台电脑 |
| 代理端口 | 10808 | 以自己的 v2rayN 实际设置为准 |
| 用户名和密码 | 留空 | 仅适用于本地代理未开启身份验证 |

### 最容易填错的地方

代理主机不要填节点服务器地址、订阅链接或手机 IP；这里连接的是电脑上的 v2rayN。端口也不要填远程节点的端口。

如果后续测试提示连接被拒绝，先检查 v2rayN 是否运行、端口是否一致。若开启本地身份验证，则必须填写实际用户名和密码。

### 网络关系

Codex 进程 → ProxyBridge → 本机 v2rayN 的 SOCKS5 端口 → 当前节点 → 目标服务

系统代理主要依赖应用主动使用代理；按进程转发用于覆盖部分未遵循系统代理的连接。是否解决当前故障，需要用日志和最终配对结果确认。

## 第二步 安装并打开 ProxyBridge

### 下载安装包

1. 打开下面的官方 GitHub 仓库，进入 Releases 发布页面。

官方仓库：[https://github.com/InterceptSuite/ProxyBridge](https://github.com/InterceptSuite/ProxyBridge)

发布页面：[https://github.com/InterceptSuite/ProxyBridge/releases](https://github.com/InterceptSuite/ProxyBridge/releases)

2. 找到包含 Windows 安装包的版本，展开 Assets，下载名称类似 ProxyBridge-Setup-X.X.X.exe 的文件。不要下载 Linux 或 macOS 安装包，也不要把 Source code 当成安装程序。

3. 若最新发布仅提供 Linux 测试版，向下查找包含 Windows Setup.exe 的正式发布。版本会更新，不必固定使用某个旧版本。

### 完成安装

4. 在下载文件夹中双击安装包。出现 Windows 用户账户控制提示时，由你确认发布者和来源后点击“是”。

5. 按安装向导完成安装。安装路径可以自选，后续规则按进程名匹配，不依赖安装目录。

6. 打开 ProxyBridge。若当前版本启动时请求管理员授权，完成授权后继续。不同版本可能通过后台服务运行，启动表现会不同。

### 成功标志

能够看到 ProxyBridge 主窗口，通常包含 Proxy、Profile、Connections 和 Activity Log 等菜单或标签。此时列表中出现 Direct 记录很正常：还没有添加 Codex 代理规则。

### 如果没有弹出安装窗口

先检查任务栏、下载文件夹和是否已有安装进程。直接在文件夹中双击安装包重试；必要时右键选择“以管理员身份运行”。没有完成安装前，不要反复叠加启动。若系统明确阻止运行，先核实官方来源和系统提示，不要关闭防护。

官方说明：Windows 版本使用底层流量转发组件。安装与首次运行应以当前版本的官方说明为准。

## 第三步 添加本地 SOCKS5 代理

以下以英文界面为例。中文界面对应“代理”“代理设置”等名称。

### 逐项填写

1. 点击顶部 Proxy → Proxy Settings。

2. 若页面是代理列表，点击 Add 或新增；若直接显示表单，在表单中填写。

| 字段 | 填写内容 |
| --- | --- |
| Proxy Type 代理类型 | SOCKS5 |
| Proxy Host 代理主机 | 127.0.0.1 |
| Proxy Port 代理端口 | 10808 或你的实际 SOCKS5 端口 |
| Proxy Username 用户名 | 未开启本地身份验证时留空 |
| Proxy Password 密码 | 未开启本地身份验证时留空 |

3. 点击 Save Changes 或保存。若有多个代理配置，记住刚保存的 127.0.0.1:10808 条目，下一步规则应选择它。

### 测试代理

4. 点击 Test Proxy Connection。输入一个你需要访问的 HTTPS 主机，例如 chatgpt.com，目标端口填 443。主机字段不填写 https:// 或网页路径。

5. 点击 Start Test，查看输出。如果报告连接或隧道建立成功，说明本地代理能够连接该测试目标。测试成功并不等于账号验证或远程控制已经成功。

6. 确认代理设置已保存，再关闭设置窗口。

### 测试失败时先处理这里

连接被拒绝：检查 v2rayN 是否运行、SOCKS5 端口是否正确。
认证失败：核对本地代理用户名和密码。
连接超时：检查节点能否访问该目标，必要时换一个已知可用节点后重测。

先让代理测试通过，再继续添加规则；不要用开启 TUN 的方式掩盖测试失败。

## 第四步 添加并启用 Codex 代理规则

### 手动添加规则

1. 点击 Proxy → Proxy Rules → Add Rule。

2. 按下表填写。Applications 中的两个进程名用英文分号分隔。

| 字段 | 填写内容 |
| --- | --- |
| Applications 应用程序 | ChatGPT.exe;codex.exe |
| Target Hosts 目标主机 | * |
| Target Ports 目标端口 | * |
| Protocol 协议 | TCP |
| Action 操作 | 选择刚添加的 SOCKS5 127.0.0.1:10808 代理 |
| Enabled 启用 | 勾选 |

3. 点击 Save Rule 或保存规则。若有更宽泛的 DIRECT 或 BLOCK 规则，将本条规则移到它们上方。规则从上往下匹配，首条匹配的规则生效。

4. 保持 Localhost Via Proxy 关闭，避免把本机回环通信也转发到代理。不要给所有进程添加通配符代理，也不要把 xray.exe、v2rayN.exe 加进这条规则。

### 为什么是这两个进程

本案例桌面应用实际进程名是 ChatGPT.exe，后台进程名是 codex.exe。程序名称和文件名不一定相同。若你的版本使用其他进程名，应通过 ProxyBridge 连接列表或任务管理器核实后再补充。

网上针对 Antigravity、language_server 或 chrome.exe 的规则不能直接套用。无关进程无需加入；不要无差别代理整个浏览器。

### 可选方法 导入本教程附带的配置

若分享者同时提供 Codex-v2rayN.pbprofile，可使用 Profile → Import Profile 导入，再在 Profile 中选中 Codex-v2rayN。仅在你的代理确实是 SOCKS5 127.0.0.1:10808 且未启用本地认证时直接使用；否则先修改代理参数。

手动配置与导入二选一即可。导入后看到配置名称，并不能单独证明流量已走代理，还要完成下一页验证。

## 第五步 验证代理并重新连接手机

### 先验证进程转发

1. 保持 v2rayN 和 ProxyBridge 同时运行，TUN 关闭。

2. 在 ProxyBridge 的 Connections 中等待 Codex 发起新连接。搜索 ChatGPT.exe 或 codex.exe；如有搜索框，输入后按 Enter。旧记录不会因为改规则而自动改成 Proxy。

3. 观察新的记录是否包含以下内容。下面是日志格式示意，目标地址和进程 ID 会变化。

ChatGPT.exe → 目标地址:443
via Proxy SOCKS5://127.0.0.1:10808

codex.exe → 目标地址:443
via Proxy SOCKS5://127.0.0.1:10808

4. 指向 127.0.0.1:10808 的连接显示 Direct 通常是预期行为，因为它是本机通信。要检查的是访问外部目标的新连接是否显示 Proxy。

5. 若仍只有外部 Direct 记录，检查配置是否选中、规则是否启用、进程名是否正确及规则顺序。必要时保存工作后完全退出并重开 Codex，让它建立新连接。

### 再验证远程控制

6. 在桌面 Codex 或 ChatGPT 应用中，进入设置 → 连接 → 允许控制此电脑，开启远程连接。旧版本菜单名称可能不同。

7. 点击 Set up 或 Add，按提示完成账号或设备验证。若显示二维码，用手机扫描并在官方 ChatGPT 应用中继续。

8. 确认电脑与手机使用同一个账号和工作区，完成要求的验证步骤。手机进入 Codex 或仍称为 Remote 的入口，选择该电脑。安卓功能入口可能随版本和发布范围变化。

9. 从手机打开或新建一个简单任务，确认电脑收到请求并能返回结果。只有完成这一步，才可以确认手机远程连接成功。

使用期间保持电脑在线、桌面应用运行并避免休眠；v2rayN 和 ProxyBridge 也需要继续运行。

## 常见问题与恢复方法

### 导入后还是无法启用远程控制

先确认新连接已经显示 Proxy。若代理测试与进程转发都正常但仍报错，保存工作后重启桌面应用再试，并检查两端版本、账号和工作区是否一致。组织账号还需确认管理员是否允许 Remote Control。此时不能继续把原因直接归结为 V2Ray。

### 开 TUN 就断网

关闭 TUN，恢复原先可用的系统代理设置。本教程不要求 TUN；TUN 断网与远程控制启用失败可能是两个不同的问题。不要在没有确认恢复方法时反复切换全局网络。

### 配置后 Codex 反而无法联网

在 Proxy Rules 中暂时取消启用 Codex 规则，或切换回原先的配置，恢复测试前状态。保持 v2rayN 原有设置，先重新测试 SOCKS5 端口。必要时退出 ProxyBridge 后重试；新连接恢复后再检查协议、端口、认证和规则。

### 重启电脑后失效

确认 v2rayN 与 ProxyBridge 均已启动、正确配置已选中。只有软件运行并加载规则后，进程转发才有效。是否开机启动由使用者自行决定。

### 分享前的检查清单

□ 代理主机和端口已按本人环境核实。
□ 代理测试通过，新外部连接显示 Proxy。
□ 本机通信保持直连，无需添加无关软件规则。
□ 手机扫码配对及简单任务已分别验证。
□ 分享的日志截图已隐藏账号、节点、IP 等个人信息。

## 补充一 安卓配对卡住时先检查聊天

补充日期  2026 年 10 月 16 日

本补充接续前文的电脑端教程。电脑已能生成配对二维码后，安卓手机扫码进入“正在配对”，但一直没有完成。进一步检查发现，手机 ChatGPT 连普通聊天也无法发送，因此先排查手机联网，再继续配对。

### 本次案例环境与最终结果

手机为红米 Turbo 4 系列，运行 Android 15，使用 v2rayNG 1.9.39；ChatGPT 版本为 1.2026.279。检查时手机实际使用移动数据，Wi-Fi 已关闭。这些版本用于记录案例，不表示必须安装同一版本。

最终将 v2rayNG 的远程 DNS 改为 https://1.1.1.1/dns-query，重新连接后，使用者确认普通聊天恢复。原代理节点、节点账号及订阅均未更换；手机远程配对的最终结果仍需单独验证。

### 先分清失败发生在哪一步

1. 扫码后完全没有识别结果：先检查扫码方式和二维码清晰度。
2. 能识别但不能打开 ChatGPT：检查应用版本、链接打开方式及是否进入官方 App。
3. 已显示“正在配对”：说明配对页面已经打开，继续检查普通聊天、网络和账号验证。
4. 普通聊天也失败：优先排查手机代理与 DNS，不要只反复扫描二维码。

### 本次排查取得的证据

| 检查项目 | 实际结果 |
| --- | --- |
| v2rayNG 的 VPN 与应用范围 | VPN 已连接，ChatGPT 已被覆盖 |
| ChatGPT 错误日志 | 反复出现 UnknownHostException，无法解析 cloudflare-dns.com |
| 经手机代理访问测试网站 | 成功返回 HTTP 204 |
| 手机 v2rayNG 本地 DNS 服务 | 已监听，但实际 DNS 查询超时 |
| 经同一手机代理使用 HTTPS DNS | 解析成功，返回 DNS 答案 |
| 修改远程 DNS 并重新连接 | 使用者确认 ChatGPT 普通聊天恢复 |

只看到“VPN 已连接”不能证明 DNS 或目标服务可用；本例中代理通道与 DNS 查询路径的表现不同。

## 补充二 安卓 v2rayNG 的详细修复步骤

适用条件：节点能够联网，但 App 报域名解析错误，或测试显示普通 DNS 查询超时。其他错误不应一律照搬。本教程无需更换原节点，也无需在手机安装 ProxyBridge。

### 第一步 记录现有设置

打开 v2rayNG，记下当前选中的节点、运行模式、远程 DNS 和分应用代理状态。截图应自行保存；不要公开节点密码、订阅链接或二维码。

### 第二步 设置 DNS

1. 打开 v2rayNG 的设置页面，找到“启用本地 DNS”，将其打开。该选项让 DNS 请求交给内核的 DNS 模块处理。

2. “启用虚拟 DNS”保持关闭。仅开启本地 DNS 在本次案例中并未恢复聊天，仍需完成下面的远程 DNS 修改。

3. 向下滑到“远程 DNS (udp/tcp/https/quic)(可选)”，点击该项，将原来的 1.1.1.1 完整替换为下面这一行：

https://1.1.1.1/dns-query

4. 点击确定或保存。注意包含 https:// 和 /dns-query；使用英文符号，不要添加空格、引号或中文标点。不要把这行填写到节点服务器、订阅地址或手机系统的私人 DNS 主机名栏。

| 选项 | 本次恢复聊天时采用的设置 |
| --- | --- |
| 运行模式 | VPN |
| 启用本地 DNS | 开启 |
| 启用虚拟 DNS | 关闭 |
| 远程 DNS | https://1.1.1.1/dns-query |
| 境内 DNS | 223.5.5.5，保持案例中的原值 |
| 分应用代理 | 排查期间关闭 |
| 代理节点 | 仍使用原来的节点 |

### 第三步 重新连接并验证

5. 返回主界面，停止 v2rayNG，再重新启动。仅保存设置而不重启连接，不能保证运行中的 VPN 使用了新配置。
6. 重新打开 ChatGPT，发送一句“你好”，确认能够收到回复。
7. 普通聊天恢复后，电脑重新生成二维码，再扫描并完成配对。电脑端 v2rayN 和 ProxyBridge 保持运行，TUN 仍关闭。

## 补充三 为什么改 DNS 后恢复

### 节点和 DNS 各负责什么

代理节点负责转发网络连接；DNS 负责把域名转换为服务器 IP。节点能够转发连接，不代表 DNS 查询也能成功。App 找不到服务器地址时，可能表现为消息发不出、一直转圈或配对停滞。

电脑和手机使用同一个节点，也可能有不同结果，因为两端的客户端、DNS 配置、路由规则和当前接入网络不同。

### 两个填写值的区别

| 远程 DNS 填写值 | 含义 |
| --- | --- |
| 1.1.1.1 | 普通 DNS 服务器地址。在本例的原配置下，DNS 查询路径超时。 |
| https://1.1.1.1/dns-query | 使用 DNS over HTTPS，经 HTTPS 传输查询；本次已测试该路径可用。 |

普通 DNS 通常使用 UDP 53 端口；这里的 HTTPS DNS 使用 HTTPS 服务。本次采用 IP 形式的地址，也避免了先解析 DNS 服务域名这一额外步骤。具体流量如何经过节点，还取决于客户端的配置。

能够确定的是：原 DNS 路径查询超时，HTTPS DNS 测试成功，修改后普通聊天恢复。尚不能确定原路径是被运营商、节点还是中间网络丢弃，也不能把原因直接认定为某一方封锁。

### 分应用代理需要一直关闭吗

不一定。关闭它是为了临时排除应用遗漏和分流影响；单独关闭后，本次聊天仍未恢复。恢复后如希望只代理指定 App，可重新配置分应用代理，并再次测试 ChatGPT、扫码所用浏览器及配对功能。

本次恢复时的组合是：本地 DNS 开启、虚拟 DNS 关闭、分应用代理关闭、远程 DNS 使用 HTTPS。重新启用分应用代理属于新的配置变化，需要另外验证，不能保证直接恢复旧规则后仍正常。

### 如果照做后仍失败

先核对地址是否完整、连接是否已重启，并区分“无法解析域名”“连接超时”“登录验证”与“服务拒绝访问”。记录错误和时间，再针对性检查。不要同时修改多个选项，也不要为排查而开启跳过证书验证。

若改动后其他应用异常，先恢复自己记录的原值并重启 VPN。HTTPS DNS 也不是所有网络环境的通用保证。

## 补充四 自动启动与 USB 辅助排查

### 电脑重启后的自动代理

本案例已配置登录 Windows 后启动 v2rayN 和 ProxyBridge，默认加载 Codex-v2rayN 配置。ProxyBridge 服务设为自动启动，规则只针对 ChatGPT.exe 和 codex.exe 的 TCP 连接，本机通信保留直连。

还添加了桌面快捷方式“ChatGPT 自动代理”：先检查并启动代理软件，等待本地 10808 端口，再打开 ChatGPT。原来的 ChatGPT 图标没有被替换；如果手动退出过代理软件，应使用新快捷方式。

这套启动项和快捷方式属于本台电脑的本地配置，不会随 Word 文档自动安装到其他电脑。其他使用者可在软件设置中开启启动选项，确认正确配置已保存，并在重新登录后检查实际代理日志。

启动脚本依赖程序实际路径及 10808 端口；移动或卸载相关程序后，需要同步更新快捷方式和启动项。只检查端口可用，不等于节点或 ChatGPT 服务一定可用。

### 什么时候需要通过 USB 排查

若仍无法定位，可用支持数据传输的 Type-C 线连接电脑，通过安卓 ADB 辅助读取 VPN 状态、相关应用版本和错误日志。USB 连接本身不会自动让手机使用电脑代理，也不是完成普通 DNS 修复的必需条件。

1. 手机开启开发者选项和 USB 调试。
2. 解锁后连接电脑，由本人确认“允许 USB 调试”的授权提示。
3. 电脑执行 adb devices，显示 device 才表示调试连接建立；unauthorized 表示仍未授权，列表为空则需检查调试开关、数据线或驱动。
4. 先进行只读检查。若系统阻止自动点击，可由本人手动打开设置，不必额外放宽其他调试权限。

诊断结束后，如不再需要调试，可关闭 USB 调试或撤销电脑授权。共享日志时隐藏订阅、账号、令牌和其他个人内容。
